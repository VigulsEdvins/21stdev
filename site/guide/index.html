What you need

Last checked: 2026-10-29

Nothing to install. About 30 minutes for your first time.

  • The unzipped folder. Open the ZIP you downloaded and extract it (right-click, "Extract all" on Windows; double-click on a Mac). The folder holds index.html, style.css, script.js and an assets folder. Keep them together.
  • A hosting account. This is the computer that shows your site to visitors. Free ones are named below; you do not need to pay for hosting to start.
  • A domain name (optional at first). The address people type, like yourname.com. Buying one costs roughly 8 to 20 euros a year. Without one you get a free address like yourname.netlify.app, which is fine for trying it out.
  • An email address you can read, for the host to send you a confirmation.

Which route? No experience: Netlify Drop (Route 1). Want it free with your own domain: Cloudflare Pages (Route 2). You already have a host with a file manager: Route 4, upload.

Route 1: Netlify Drop (easiest)

Last checked: 2026-10-29

  1. Open https://app.netlify.com/drop in your browser.You should now see: A page with a large box that says to drag and drop a folder.
  2. Drag the unzipped folder (the one holding index.html) onto the box. Drag the folder, not the ZIP file.You should now see: A progress bar, then your site with a web address ending in .netlify.app.
  3. Click the address. Your page opens in a new tab.You should now see: Your page, with its pictures. If it is blank, see "If something goes wrong" below.
  4. Create a free Netlify account when it asks, so the site is not deleted after an hour.You should now see: The site listed under "Sites" in your Netlify account.

Netlify reads the _headers file in your folder, so the security and caching rules are applied for you.

Route 2: Cloudflare Pages (free, with your own domain)

Last checked: 2026-10-29

  1. Create a free account at https://dash.cloudflare.com/sign-up and confirm your email.You should now see: The Cloudflare dashboard.
  2. In the left menu choose "Workers & Pages", then "Create", then the "Pages" tab, then "Upload assets".You should now see: A form asking for a project name.
  3. Type a project name (letters and dashes only). This becomes name.pages.dev. Click "Create project".You should now see: A box to drop files.
  4. Drag the unzipped folder into the box, or use "Select from computer" and choose the folder. Click "Deploy site".You should now see: A "Success" message and a .pages.dev address.
  5. Click the address to open your site.You should now see: Your page.

Cloudflare reads _headers too. To update later, open the project and choose "Create new deployment" to upload the new folder.

Sent to GitHub? Already sent the files to your GitHub account from edvlabs? Choose "Connect to Git" instead of "Upload assets", pick your repository, leave the build command empty and set the output folder to /. Each new commit then goes online by itself.

Route 3: GitHub Pages

Last checked: 2026-10-29

  1. Create a free account at https://github.com and make a new repository (the "+" at the top, "New repository"). Choose Public.You should now see: An empty repository.
  2. Click "uploading an existing file", drag in the contents of the unzipped folder (the files and the assets folder, not the folder around them), and click "Commit changes".You should now see: The files listed in the repository.
  3. Open the repository "Settings", then "Pages". Under "Build and deployment" choose "Deploy from a branch", branch main, folder / (root), and Save.You should now see: After a minute or two the page shows "Your site is live at ...".
  4. Open that address.You should now see: Your page.

GitHub Pages ignores the _headers file, so the extra security and caching rules are not applied there. It works, but Netlify and Cloudflare Pages protect your visitors a little better.

Route 4: An ordinary web host (cPanel, FTP, file manager)

Last checked: 2026-10-29

  1. Log in to your hosting control panel and open "File Manager" (or connect with an FTP program using the details your host emailed you).You should now see: A list of folders. Look for one called public_html, www or htdocs.
  2. Open that folder. If it holds a placeholder page such as index.php or default.html, delete or rename it.You should now see: An empty folder.
  3. Upload everything from inside the unzipped folder: index.html, style.css, script.js, the assets folder and the rest. Keep the folder structure.You should now see: The same files listed, with assets still a folder.
  4. Open your domain in a browser.You should now see: Your page.

_headers is ignored by most ordinary hosts. That is harmless.

Connect your own domain

Last checked: 2026-10-29

  1. Buy a domain from a registrar (for example Cloudflare Registrar, Namecheap, or a local one). Choose a short name; .com or your country ending.You should now see: The domain listed in your registrar account.
  2. In your host (Netlify: "Domain management"; Cloudflare Pages: "Custom domains"), click "Add a domain" and type it, for example yourname.com.You should now see: The host shows what to change: either two name servers, or two DNS records (an A or CNAME record).
  3. In your registrar, either replace the name servers with the two the host gave you, or add the DNS records exactly as shown. Save.You should now see: The registrar shows the new values.
  4. Wait. It usually takes minutes, sometimes up to a few hours. The host turns on HTTPS (the padlock) by itself.You should now see: The host shows the domain as "Active" or "Verified" and the address opens with a padlock.
  5. Choose www or no www as the main address, and let the host redirect the other one to it.You should now see: Typing either version lands on the same page.

If it still does not work after an hour: check you copied the values with no extra spaces, that you changed them at the registrar where the domain is registered, and that old records for the same name were removed. Then ask your host's support; they see the same screen you do.

After it is online

Last checked: 2026-10-29

  1. In the builder, open Step 5 and type your real web address when asked ("What will your web address be?"). Download again and upload the new folder.You should now see: The new sitemap.xml and the right address inside the page.
  2. Open Google Search Console at https://search.google.com/search-console, add your site, and submit https://your-address/sitemap.xml under "Sitemaps". Do the same at https://www.bing.com/webmasters.You should now see: "Success" next to the sitemap.
  3. Open your site on your phone, on mobile data, not your home wifi.You should now see: The page looks right and loads in a few seconds.
  4. Click every link and button. Send yourself a message through the contact form, if you have one.You should now see: Everything goes where it should (see the form note below).

What to expect from Google: it takes days to a few weeks to list a new site. Where you appear depends on your content, your links and your competition. edvlabs cannot promise a ranking and nobody honest can.

Contact forms on a static site

Last checked: 2026-10-29

A page made of plain files has no back end, so a contact form on its own cannot send anything. Do one of these, or the form goes nowhere:

  • Use a form service. Formspree, Web3Forms and Netlify Forms catch the form and email it to you. They have free plans.
  • Link to an email address or a WhatsApp number instead of a form.
  • Use your own back end if you have a developer.

Example with Formspree: create a free account at https://formspree.io, make a new form, copy its address (it looks like https://formspree.io/f/abcdwxyz), then in the builder open the form block and paste that address as the form's action. Send a test message and look for it in your inbox.

Email on your own domain

Last checked: 2026-10-29

Email like hello@yourname.com is not part of the website. Get it from your registrar, Google Workspace, Zoho or Fastmail. Be careful: if you move your domain to a new host and change the MX records by accident, your email stops arriving. Only touch the A, CNAME or name-server settings the host tells you to.

Updating later

Last checked: 2026-10-29

  1. Change the page in the builder (or, if you bought the editor, in the editor page) and download again.You should now see: A new ZIP.
  2. Upload it the same way as the first time: Netlify "Deploys", Cloudflare "Create new deployment", GitHub commit, or the file manager.You should now see: The change visible after a minute. If you still see the old page, refresh the page hard (Ctrl+Shift+R, or Cmd+Shift+R on a Mac).

Keep the first ZIP. It is your backup.

If something goes wrong

Last checked: 2026-10-29

ProblemWhat to do
Blank white pageYou uploaded the ZIP itself or the outer folder. Upload the files inside the folder, with index.html at the top.
Pictures or styles missingThe assets folder or style.css was left out, or renamed. Upload them again, keeping the names.
"404 Not Found" when you refresh a pageThe file name is different from the link. Check names are lower case and match exactly.
You still see the old versionYour browser kept a copy. Hard-refresh, or open the address in a private window.
"Not secure" warningThe address starts with http://. Use https://. For your own domain, wait for the host to finish turning HTTPS on.
The domain shows a host's parking pageThe DNS change has not spread yet, or the records are wrong. See "Connect your own domain".

Still stuck? Write to the support address on edvlabs.com/contact and include: the address of your site, which route you followed, the step you are on, and a screenshot. Never send us a password, API key or card number. We will never ask for one.
